[P1] Harden authorization when patching agent records

The new PATCH /api/agents/{agent_id} endpoint attempts to block non‑admins from editing someone else’s agent, but the check only rejects the call when the payload’s userId is neither the caller’s ID nor null. An attacker can bypass this simply by including {"userId": "<their own id>"} in the body; the condition at the top then evaluates to false and the request proceeds, allowing them to change status, metadata, and even reassign ownership of another user’s agent. This is a privilege escalation because unprivileged users can overwrite arbitrary agents as long as they know the id. Consider validating against the current ownership before applying updates, regardless of the requested userId, or ignoring client‑supplied userId for non‑admins.
